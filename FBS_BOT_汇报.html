System Design

用 3 个 Agent 拆分任务流，方便后续持续接入更多官方仓能力

整体架构不是把所有功能写在一个大 Prompt 里，而是用主控分发 + 业务查询 + 报告交付的方式承接迭代，后续新增项目、站点、报表或知识库时，只需要扩展对应 Agent。

01

Router Agent

识别用户意图、判断缺失参数、做 GGP / RM / 站点 / 项目类型路由，把问题分发到正确任务流。

02

FBS Operation Helper

完成主要官方仓查询：卖家表现、库存风险、项目达标、RM 看板、入仓 Pitch、基础操作指南。

03

Report Agent

整合卖家表现、库存、项目、激励和入仓机会，生成完整 PDF / HTML 拜访材料。

为什么要做 Multi-Agent？

因为官方仓问题会不断扩展，Multi-Agent 后续迭代更稳，也方便链接 workflow 依靠 data API 取数。

交互设计

用户只需要自然语言提问，系统自动判断是走单点查询、RM 管理看板，还是完整报告生成。

Current Pain Points

目前工作流需要跨越多张表格，无法一键看到卖家全局表现，各板块信息高度分散

01

卖家复盘需要来回切 16-20 张表

整体 ADO、店铺表现、库存、OOS、TAGGING、SKU Pitch 分散在不同数据源里，RM 要先查表，再手动判断原因。

02

项目达标分散在多个站点与项目 tracker

Free Trial、Increase、VIP、广告金返还等项目各自维护，单个项目可能就有五六张表。

03

难以用全局视角定位卖家表现变化的真正原因

卖家整体单量下滑，可能来自某个热销品缺货；站点整体提升，也可能来自某几个产品爆发。人工查表很难快速串联“卖家-站点-店铺-商品”。

原始数据源：表现、库存、项目、激励、图片与操作知识分散在多个表 Before
From Data To Action

从数据整合到行动建议，Bot 一键转成增长、风险、达标缺口和补货动作

核心不是把表格复制出来，而是把分散数据翻译成“现在应该跟进什么”。

1-2h

预计每周为 RM 节省 1-2 小时，不必在多个表格和项目 tracker 之间来回定位数据。

P0/P1

直接输出优先级

把缺货、ADO 下滑、TAG 风险、项目差距转成 P0/P1/P2 行动清单。

PDF

沉淀可交付材料

支持生成卖家拜访报告、RM 项目看板和官方仓操作指南，统一团队对外口径。

Function Preview

主要涵盖官方仓全部功能，7 大功能预览

卖家整体 FBS 表现复盘

从 GGP、站点、店铺和行动建议四个层级看整体表现，帮助 RM 快速判断 FBS ADO 下滑或增长的原因。

  • 按 TTL / PH / MY / SG / TH 看表现
  • 定位缺货、TAGGING、站点空白等风险
  • 滚动查看完整复盘输出

产品层库存风险诊断

Bot 会把缺货产品、头部热销品、黑库风险和 FBS TAGGING 风险转成补货行动清单。

  • 识别 DOC 不足 30 天产品
  • 标记热销品中最急需补货 SKU
  • 输出补货、IR、库存监控建议

卖家项目达标与激励汇总

项目视角覆盖已入仓和未入仓卖家机会，不只看 FBS 表现，也看 Free Trial、VIP、Increase、广告金等任务进度。

  • 查看项目入选和达标率
  • 识别挑战目标差距
  • 同步广告金与优惠券激励

RM 名下卖家项目看板

RM 输入邮箱即可查看名下哪些 GGP 参与项目、哪些未达标、哪些需要优先跟进。

  • 按 RM 名下 GGP 自动过滤
  • 未达标和高风险卖家优先展示
  • 输出可执行行动建议

新仓 Pitch 与推荐入仓商品

先展示可直接发给卖家的入仓推荐摘要，再展示带商品图片的爆品入仓明细。

  • 区分已加入 FBS 与未加入 FBS 店铺
  • 输出推荐入仓 item 数
  • 结合商品图提升卖家沟通效率

卖家官方仓报告一键生成

将卖家整体表现、库存风险、项目达标、激励和推荐入仓产品整理成可用于拜访的 PDF / HTML 材料。

  • 默认老板汇报版结构
  • 保留重点结论和 Next Actions
  • 适合拜访卖家前快速生成

官方仓基础操作指南

围绕入仓流程、提品审核、IR、ISR、送仓交接等节点，帮助 RM 和卖家快速了解官方仓操作规则。

  • 把官方手册转成可问答流程
  • 风险点与正确做法并列展示
  • 减少重复沟通成本
Business Impact

让 RM 更快发现问题、推动卖家行动，提升 FBS 各项任务推进效率
